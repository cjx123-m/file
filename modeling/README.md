# 需求预测与调度模块

## 流水线

`python -m modeling.run_all` 依次执行：

1. `features.py`：读取 `output/rides_clean.csv`，聚合为完整站点小时面板；
2. `train.py`：按时间切分训练/测试，训练 4 个回归模型并评估；
3. `visualize.py`：输出模型对比、预测效果和特征重要性图；
4. `dispatch.py`：读取模型预测与 B 的站点时段流入比例，运行调度仿真。

## 目录职责

| 文件 | 作用 |
| --- | --- |
| `common.py` | 路径、时段口径、数据加载、站点编号与距离工具 |
| `features.py` | 站点小时需求聚合、时段/会员/车型/滞后特征 |
| `train.py` | 模型训练、MAE/RMSE/R²/WAPE、模型保存、特征重要性 |
| `visualize.py` | 预测效果图 |
| `dispatch.py` | 安全库存阈值 + 最近邻调车仿真 |
| `run_all.py` | C/D 子流水线入口 |

## 为什么用站点小时需求

骑行明细中的每条记录是一次“已发生的骑行”，不能直接当作需求量。先把明细聚合为
`station_key × timestamp` 的借出次数，再对不存在的组合补 0，才能训练真正的需求预测模型。

## 防泄漏与回测

- 最后 7 天为测试期，之前为训练期，不随机打乱。
- 站点画像、会员占比画像、电动车占比画像只用训练期计算。
- 当前小时的会员/车型构成属于目标相关变量，不作为特征。
- 前一日同小时会员/车型占比、前一日需求、前一小时需求可作为 one-step-ahead 特征。
- Ridge、随机森林和梯度提升都处理了缺失的滞后特征（首日或首周无历史）。

## 调度仿真

调度单字段包括 `timestamp, from_station_key, to_station_key, bikes, distance_km`。
所有参数集中在 `DispatchConfig`，方便修改初始库存、站点容量、安全库存、车辆容量和距离半径做敏感性分析。

注意：当前仿真用 B 的月度站点时段 `inflow/outflow` 比例近似小时还入量，并使用测试期实际需求评价服务效果。
它适合课堂演示策略方向和联调接口，不适合直接作为生产调度承诺。
